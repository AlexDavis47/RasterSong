# RasterSong documentation

RasterSong is a video editing tool that lets video and audio merge, so that effects built from audio act directly on
every pixel. The documents below are split by subject; each one stands on its own and links to the others where it
leans on them.

> **Status (October 2026):** RasterSong is being rebuilt from the ground up. The November 2025 prototype (FFmpeg
> decoding + egui viewer) is preserved under the `prototype-2025` tag for reference only and is not being built
> upon. These documents are the source of truth for the new architecture.

## Index

**Concepts and model**

- [Concepts](concepts.md): the core idea, the basic workflow, the design principles.
- [Signals & units](signals-and-units.md): the one `Signal` type, layouts and tags, rate matching, user-facing units, tempo.

**Engine and media**

- [Render engine](engine.md): crate layout, the sequential schedule, warmup and seeking, the frame cache, dynamic playback, preview resolution, Audio Output, export, performance.
- [Media layer](media.md): FFmpeg decode and encode behind one trait.

**Nodes and graphs**

- [Node authoring](node-authoring.md): the node contract, adding a node, parameters and modulation.
- [Node behavior](node-behavior.md): shared per-node settings, range conversion, channels and interleaving.
- [Node reference](nodes.md): every node's ports and parameters. Generated by `cargo xtask docs`; do not edit by hand.
- [Graph files](graph-format.md): the JSON format.

**Application**

- [Desktop app](app.md): preview, node editor, inspector, timeline, keys, projects.
- [Text and languages](text.md): where every user-facing string lives, the key scheme, adding a language.

**Project**

- [Development](development.md): setup, getting started, packaging and releases.
- [Testing](testing.md): the test layers and what each proves.
- [Licensing](licensing.md): the RasterSong license, FFmpeg, codec patents, dependencies.
- [Benchmarks](benchmarks.md)
- [Roadmap](roadmap.md): phases, and the backlog from hands-on testing, grouped by workstream.
- [Decisions](decisions.md): decisions made, with their reasons, and the ones still open.

Working examples live in [`examples/graphs/`](../examples/graphs).

## Keeping these documents healthy

- One subject per file. If a section grows a second subject, split it.
- State a fact in one place and link to it from elsewhere.
- `nodes.md` is generated; CI fails if it is out of date (`cargo xtask docs --check`).
- When a roadmap item ships, tick it and, if it changed how something works, update the document that describes
  that thing in the same change.
